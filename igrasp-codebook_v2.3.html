A. How to use this document

Each participant's response to a conjecture receives seven codes. Five are verbal reasoning codes (Intuition, Insight, General, Logical, and Operative), and two are gesture codes (Dynamic Gesture and Non-dynamic Gesture). Every code is 1 when its feature is present and 0 when it is absent, except Intuition, which has additional values, and Operative, which has the additional value 1_retold (see its card). The answer key for the conjectures is provided separately, and Section D repeats each statement with its truth value.

Work through each code in the same order. Read the code's decision card in Section B, apply its test in the order written, and take the card's default when in doubt. Then apply any cross-cutting rule in Section C that fits the response. Finally, compare the response with the anchor pair for that conjecture and code in Section D. The anchors show how the general rule applies to actual responses, and they never create a rule for a single conjecture. When a card and an anchor appear to disagree, the full definitions in Section E decide.

The anchors are verbatim excerpts from de-identified transcripts, so the words shown are the participant's own. In the examples carried over from earlier versions, fillers ("um," "uh," "like"), false starts, and immediate repetitions ("the, the") were removed. The examples added in version 2.2 are quoted exactly as transcribed, fillers included. In both, omissions are marked [...], and transcription errors are left as they appear. Rule C6 explains how to handle transcripts whose speaker labels are wrong or missing.

Keep this document open while coding. Coders who are new to qualitative coding should first read the introduction for beginners in the project folder.

B. Decision cards

Intuition

Question. What was the participant's first verdict, and was it correct?

Test, in order. (1) Find the first true/false verdict stated after the statement is read. (2) If it is explicit, score it against the key: correct = 1, incorrect = 0. (3) If no clean verdict is stated, infer the stance from a minimal cue ("yeah," "no," "I don't think so") or from reasoning that stays consistent to the end: correct = 1_inferred, incorrect = 0_inferred. (4) Only if nothing can be inferred, code missing.

Default. Infer before you settle on missing. Later changes of mind never alter the code; it is locked to the first verdict.

Common confusions. For i5, the verdict is scored by Rule C5, not by the key alone.

Insight

Question. Is at least one correct, relevant mathematical idea present?

Test, in order. (1) Set aside the verdict; look at the ideas offered. (2) Is there a valid idea, relationship, computation, or counterexample that bears on why the conjecture holds or fails? If yes, and nothing said about it is mathematically wrong, code 1. (3) If the only content is a restatement of the conjecture, a wrong idea, or no idea, code 0.

Default. Generous. If the spirit of a valid idea is there and the reasoning is not wrong, code 1, even when it is partial or loosely worded.

Common confusions. A correct verdict with no idea is 0. A wrong verdict can still carry a correct idea (code 1). Counterexamples are judged by Rule C4.

General

Question. Does the participant say, in their own words, that the claim holds for every case, or give a specific reason about the kind of object the conjecture names (for example, triangles in general and not one triangle) and tie it to what the conjecture is about?

Words used here. The conjecture is the printed statement the participant judges, and its claim is what it says is true. A case is one particular example, such as one triangle. The property is the one feature the conjecture is about (the list is in Section E.3). A word for every case is a word or phrase that makes a sentence apply to all cases at once, such as "any," "always," or "wherever."

Test, in order.

  1. Ignore the conjecture read back. Ignore any part in which the participant reads the conjecture aloud or repeats its wording. Putting the conjecture in other words without adding anything, or explaining what its words mean, counts as repeating it. If nothing else is left, code 0. Only the conjecture is ignored: check what the participant says about the video or the VR activity against steps 2 to 5 like anything else.
  2. A counterexample. If the conjecture is false and the participant gives a valid counterexample (Rule C4), code 1.
  3. A case extended. The participant works through one case and then says, in any words, that the result holds for cases they did not try ("and that would apply to other triangles too"): code 1.
  4. The claim, said for every case. The participant says that the claim is so, or is not so, using a word for every case that the conjecture does not already use for the same objects (such as any, every, always, never, wherever, or no matter): code 1. Section E.3 has the full list and says when such a word does not count. Saying that something which differs from case to case makes no difference counts in the same way ("how far apart they are doesn't change the angles").
  5. A specific reason about the kind of object the conjecture names. Code 1 if a reason passes all three checks.
    • 5a. It is about the kind of object, not one occasion or one example. The participant does not need to say "all" or "every": a reason that speaks of the kind of object without picking out a particular one can pass ("the more sides, the bigger the angles get"). It fails this check if it is (i) told as something the participant did or saw, (ii) about one case only, or (iii) a doubt.
    • 5b. It names something specific. It names a part, a quantity, a dimension, or a relationship in the object, or it does a calculation step that uses no measurements of any one object ("you multiply by two three times"). Naming only the object or its overall shape fails.
    • 5c. It is tied to the conjecture. The reason itself says something about the property, or the participant says what the fact means for the property. A fact followed only by "so true" or "so false" fails.
  6. Otherwise code 0.

Default. Strict. When you cannot tell whether a step or a check is met, treat it as not met. Judge the response as it is worded, and do not guess what the participant had in mind.

Common confusions.

  • Step 5 needs no word for every case: "you multiply by two three times, so it's eight" is 1.
  • "Wherever you cut it, it's a circle" is 1 by step 4, because "wherever" is the participant's word and not the conjecture's.
  • "A sphere is a ball shape, so it's a circle" is 0, because it names the overall shape and no part (check 5b).
  • "They're not parallel, so they have to cross somewhere" is 0 when the conjecture is about bisecting, because it is tied to a different property (check 5c).
  • "Angles add to 180, so true" is 0, because the participant states a fact and then answers "true" without saying what the fact means for the property (check 5c).
  • "When I moved it, the angles stayed the same" is 0, because it is told as something the participant did (check 5a). The same sentence can still earn Operative, because the two codes ask different questions.
  • On i1, whose claim is that the angles get larger, "the angles stay the same" with nothing else is 0, because it only says that the claim is not so.
  • "They shrank it flat in the video. Flat is the smallest it can get, and there the two sides only equal the third, so in a real triangle they add up to more" is 1: the video is where the idea came from, and the reason itself is about triangles in general (check 5a).
  • "If one angle were off, one of the sides would come out different, so they wouldn't be similar" is 1: a reason about the opposite situation, in which what the conjecture starts from is not so, is checked against 5a to 5c like any other reason.
  • A hedge on where the participant ends up does not matter ("so a third seems like a nice number"; "so I guess false"). Check 5a fails a reason only when the reason itself is a "maybe."

Section E.3 gives the details of each step.

Logical

Question. Does the participant state a deductive chain?

Words used here. A chain is a starting point, at least one middle step, and a conclusion, joined by two links that the participant says. The conclusion is that the conjecture's claim is so or is not so. The verdict is the true-or-false answer.

Test, in order.

  1. The verdict is not a step. Ignore any part in which the participant reads the conjecture aloud or repeats its wording. The verdict ("so it's true"; "my final answer is false") is scored by Intuition and Insight, and here it is never the starting point or the middle step.
  2. A counterexample. If the conjecture is false and the participant gives a valid counterexample and says what the case produces, not only that the conjecture fails, code 1 (Rule C4).
  3. A calculation. If the participant gives the numbers they start with, what is done to them, and the number that results, code 1 ("each angle is 90 and there are four, so 360"; "a cube of one, you change it all to two, and you end up with eight"). One example is enough, and the arithmetic does not have to be said aloud. A case with only its outcome is not a calculation ("I pictured a square and it's 360"; "I tried it and it worked").
  4. A chain with two links. Otherwise, code 1 only if you can point to all three parts, and to both links between them, in the participant's words.
    • A starting point: a fact, a definition, a case, a supposition, or something the conjecture gives.
    • A middle step that the participant draws from the starting point ("the angles add to 180, so the third angle is fixed"). It has to be something new. The starting point said again is not a middle step, and neither is the claim itself or its denial ("so the angle doesn't change," on i1; "so they are similar," on b4, where "so the third angle matches" is a middle step).
    • The conclusion, which the participant reaches from the middle step. The verdict can stand as the conclusion when the middle step is given as the reason for it ("the angles add to 180, so the last angle is the same, so true").
  5. Otherwise code 0.

Default. Strict. When you cannot point to the middle step and both links, code 0. The reasoning does not have to be correct.

Common confusions.

  • One reason and the conclusion, or one reason and the verdict, is one link and is 0, however good the reason. Each of these is 0: "angles add to 180, so true"; "the chord is always the same distance from the center, so the bisector goes through it"; "a sphere is round, so any cut is a circle"; "even if the distance increases, the angle should not change, because the line between them gets longer too" (one reason is given for the claim's denial, and nothing is drawn from that reason before the conclusion).
  • What the conjecture gives can be the starting point when the participant draws from it a new fact that the conjecture does not mention ("two pairs of angles are the same, so the last one would be the same as well"). The verdict can then stand as the conclusion. "There are two pairs, so they have to be similar" is 0.
  • A construction is a chain when the participant builds a figure, says which part of it is the line or shape the conjecture is about, and states the fact that decides the question ("a right triangle from the diagonal and two edges; the diagonal is its hypotenuse; the hypotenuse is the longest side"). If the participant does not say which part it is, code 0.
  • A correct picture or conclusion with no steps is 0 ("it just looks longer going through the middle"), and so is naming a theorem or a lesson in place of steps. A step still counts when the participant credits it to memory or a lesson.
  • An action in VR retold with its outcome is Operative's matter, not Logical's, unless the participant also states a middle step.
  • A complete chain built on a misreading of the conjecture is Logical 1 with Insight 0 (rare).

Operative

Question. Does the participant describe doing something to the object or with its numbers, themselves or as something anyone could do, and say what comes of it?

Words used here. A doing is something the participant describes carrying out; step 1 lists the kinds. A report only tells what happened or what was seen, and nobody is described as doing anything to the object. The VR activity is what the participant performed or watched in VR for that conjecture.

Test, in order.

  1. Find a doing. It is one of three kinds.

    • An action on the object, told with "I" (or "we") or "you" as the one who acts ("when I moved the vertex down"; "if you cut it through the tip"; "wherever you cut it").
    • A calculation that the participant carries out on stated numbers ("four angles of 90 make 360").
    • A case made up and followed to an outcome: the participant chooses a particular arrangement and says what then holds for it ("if two sides are the same length, together they're longer than the third").

    A change to the object that neither "I" nor "you" is said to make, whether it is reported ("the lines got closer"; "when he pulled it down") or only supposed ("even if the distance increases"), is a doing only when the participant follows it further in their own words and says what else changes with it ("the angle stays, because the line across gets longer along with it"). A reason that names nothing else that changes ("because the lines stay parallel") does not make it a doing. When it counts, it is entered as 1.

  2. Check for a result. The participant says what the doing produces.

  3. Check that the result is about the conjecture's property, and not only what the conjecture tells you to start with ("the sides doubled").

  4. Code. If all three hold, code 1; otherwise code 0.

    • On a VR conjecture (i1 to i6), ask one more question: is the VR activity, retold with its result, the only doing? If it is, enter 1_retold in place of 1 ("when I moved the vertex down, it met the base"). If the response has any other doing, enter 1.
    • Never enter 1_retold on a baseline conjecture (b1 to b6).

Default. Strict about whether the three things are there, lenient about how well they are said. Start at 0 and move to 1 only when you can point to the doing, its result, and what the result has to do with the property, in the participant's words. A result still counts when it is said with uncertainty, loosely worded, revised, or wrong.

Common confusions.

  • A report is not a doing. Each of these is a report: the object does it by itself ("the lines got closer"); the sentence is passive ("when it was moved"); someone else does it ("when he pulled it down"); the participant says only what they saw ("I saw a circle"). A report counts as a doing only when the participant follows the change further (step 1). Mentioning the video or the VR activity does not make a response a report; look at who is described as acting.
  • Repeating the conjecture is not a doing. "If you double all the sides, it's eight times bigger" only repeats the conjecture and is 0. It counts as a doing if the participant adds a step or a result that the conjecture does not give ("doubling each one multiplies by two three times"). On i2 and i3, whose statements are worded with "you," a sentence with "you" that gives only the action and the result printed in the conjecture is the conjecture repeated, and is 0.
  • Retelling the VR activity is 1_retold. The participant tells it as what they did ("when I unrolled it, the width was twice the distance across"), or tells it with "you" and gives a result that the conjecture does not give ("when you pull the top down, it lies flat").
  • "Go from the top corner to the bottom corner" does nothing to the object; it only follows a line that is already there.
  • A conclusion drawn from one fact to another, with nothing done and nothing calculated, is not a doing. Judge it separately under Logical.
  • Supposing only that the claim is false and saying what would follow ("if the two sides together were not longer, it would be a flat line") chooses no arrangement and is not a doing; judge it under Logical. A particular arrangement is still a made-up case when the claim fails for it ("if each side were half as long as the third, they couldn't meet").
  • A calculation can earn Operative and Logical together.

Dynamic Gesture

Question. Does at least one hand gesture depict an object, or part of one, undergoing a change?

Test, in order. (1) Identify the representational gesture units in the response (Rule C7), and ignore beats, self-touch, and incidental movement. (2) For each unit, ask whether the participant does something to the imagined object or sets it in motion. The participant exercises agency on the object when the hand acts on it by turning, sliding, folding, stretching, compressing, cutting, or building it. The gesture adds motion to the object (kineticity) when the hand stands for the object, or a part of it, and moves as the object moves or changes. In either case the object is shown in one state and then another. (3) If at least one unit does so, code 1; otherwise, code 0.

Default. Code from the hands, not the speech. The question is what happens to the object, so a moving hand is not enough. If no unit acts on the object or sets it in motion, code 0.

Common confusions. Hands also move in order to depict. A hand that moves into position, outlines a shape, traces a line or arc that is already part of the figure, or points is showing the object as it is, and that unit is Non-dynamic. Tracing is Dynamic only when the hand carries the object, or its moving part, along its path. A unit that both holds a form and moves to change it is Dynamic (Rule C7).

Non-dynamic Gesture

Question. Does at least one hand gesture depict an object, or part of one, held static?

Test, in order. (1) Identify the representational gesture units in the response (Rule C7). (2) For each unit, ask whether the gesture only depicts the object or a part of it, with no agency exercised on the object and no motion added to it. Such a unit shows the object's shape, outline, size, or location, points to or holds a part, or traces a line or arc that is already part of the figure. (3) If at least one unit does so, code 1; otherwise, code 0.

Default. Code from the hands, not the speech. One qualifying unit is enough, and the number of units does not matter.

Common confusions. Both gesture codes can be 1 in the same response when separate units qualify. A single unit that both holds a form and changes it is Dynamic only, although a separate static unit can still earn Non-dynamic.

C. Rules that cut across codes

C1. The codes are independent, although correlated. No code requires another. Intuition and Insight are validity codes, which judge whether the content is correct. General, Logical, and Operative are form codes, which judge what kind of justification the participant offers, regardless of whether it is correct. The form codes follow Harel and Sowder's three characteristics of the transformational proof scheme, namely generality, operational thought, and logical inference (Harel & Sowder, 1998, p. 258; Harel, 2007, p. 67; Harel & Sowder, 2007, p. 809). A form code can therefore be 1 when the content is wrong, and Section D includes such cases. The gesture codes are coded from what is observed, independently of the verbal codes and of each other.

C2. One verbal code is generous and three are strict. Insight is coded generously, so a response earns 1 when the spirit of a valid idea is present and the reasoning is not wrong. General, Logical, and Operative are coded strictly. Start each at 0, and change it to 1 only when its defining feature is present in the participant's own reasoning rather than inferred by the coder. When in doubt, these three codes stay at 0. A response whose only reasoning is the conjecture's own wording is 0 on all three. So is a response whose only reasoning is a formula, rule, or fact that the participant states from memory ("I remember," "using my knowledge from high school") without saying how it applies and without calculating with it, although such a response can earn Insight. If the participant gives up an earlier explanation, judge only the later one. You can tell this has happened when their answer switches or when they take the explanation back in words ("never mind," "actually, no"). This applies to every code except Intuition, which stays locked to the first verdict.

C3. Absence is 0, except for Intuition. Every code except Intuition is 0 when its feature is absent. Only Intuition may be coded missing, and only after an attempt to infer a stance has failed.

C4. Counterexamples must be valid. A counterexample is valid only if it meets three conditions. It must be mathematically correct, and it must actually refute the conjecture. Its case must also be named specifically enough to check (a cut through the cone's tip, or a trapezoid with one base much longer than the other). A generic case ("a shape where one line is steeper") does not meet the third condition. A polygon named by its number of sides ("a triangle," "a hexagon") is specific enough even when the participant does not say "regular," because the angle sum depends only on the number of sides. A cut through a cone that is called vertical, down the middle, through the tip, or perpendicular to the base is specific enough when the participant names a triangular result.

A valid counterexample earns General = 1. It also earns Logical = 1 when the participant states what the case produces, and not only that the conjecture fails. The stated result may be a resulting shape, sum, or crossing point, or a feature of the result such as a straight edge or a corner, and it may be loosely worded ("somewhat of a triangle," "it comes to a point").

An incorrect counterexample earns neither General nor Logical, and neither does a counterexample whose own description mixes correct and incorrect claims (for example, "an isosceles trapezoid bisects but others do not," or a "concave trapezoid"). Code Insight for such a response on its own merits.

Validity is judged on the case named and on what is claimed of it, without regard to the rest of the response. A wrong remark beside a valid case ("a triangle is 180, and I don't think a square counts as a polygon") therefore does not undo the case. Nor does a loose estimate along the way when the case in fact refutes the conjecture.

An argument that a false conjecture is false, with no particular case named, is not a counterexample. For General it is judged at steps 3 to 5 of General's card.

C5. Special case for i5 (Plane and Sphere): the verdict depends on the reasoning. Intuition and Insight on i5 are scored by the argument that accompanies the verdict.

  • An argument for "false" because a tangent plane meets the sphere at a single point earns Intuition = 1 and Insight = 1.
  • An argument for "true" because a point is a degenerate circle, so that the intersection is always a possibly degenerate circle, also earns Intuition = 1 and Insight = 1. This level of specificity is required.
  • An argument for "true" because "wherever you cut it, it's a circle" earns Intuition = 0 and Insight = 0, because it ignores the tangent case.
  • An argument for "true" in which the participant names the case where the plane only touches the sphere and says that the result there is different, but sets it aside ("at exactly one point it would be different, but that doesn't count here"), earns Intuition = 0 and Insight = 1. The participant shows awareness of the case, which earns Insight, but argues "true" without the degenerate-circle argument, so Intuition stays 0. Setting the case aside in this way is not giving up an explanation under Rule C2.

If the participant argues "true," the counterexample rule does not apply, and a response that misses the tangent case is Insight = 0.

For General on i5, apply General's card as for any other conjecture. "Wherever you cut it, it's a circle" earns General = 1 by step 4, because "wherever" is the participant's word and not the conjecture's, even though the same response earns Intuition = 0 and Insight = 0. "A sphere is a ball shape, so it can only be a circle" earns General = 0, because it names the overall shape and no part, and "can only be a circle" is the conjecture's wording.

For Logical, the reasoning has to derive the circle. The equidistance argument ("every point on a sphere is the same distance from the center, so any slice is a set of points at one distance") earns Logical = 1. "A sphere is round, so any cut is a circle" earns Logical = 0, because roundness alone does not explain why the cut must be a circle (an egg is round too).

C6. Transcripts that include the researcher's lines. Code only the participant's reasoning. The researcher's reading of the statement, prompts, and encouragement never count toward any code. In some transcripts the participant's speech is labeled "Researcher," or the speakers run together. In those transcripts, use the content to tell the speakers apart, and do not credit a passage to the participant unless the attribution is clear. Speech after the researcher has moved to the next statement belongs to the next response.

C7. Coding gestures. Code only representational gestures, which depict geometric content such as a shape, a part, a location, or a transformation. Ignore beat gestures, self-touch, and incidental hand movement. A gesture unit begins when the hands leave rest, depicts the object or its transformation, and ends when the hands return to rest, and its onset and offset are treated as visibly recognizable. The gesture unit is what is judged, and the response is what is coded. Judge each unit separately, and code a gesture code 1 when at least one unit anywhere in the response qualifies for it, so the number of gestures does not matter. A unit is Dynamic when the participant acts on the imagined object (agency) or sets it in motion (kineticity), and Non-dynamic when the gesture only depicts the object or a part of it (Sections E.6 and E.7). If a single unit both traces or holds a static form and moves to change it, code that unit Dynamic. A separate static unit can still earn Non-dynamic. Each gesture unit counts toward one of the two gesture codes only: a unit judged Dynamic is not also counted as Non-dynamic. A response can still earn both codes when it has separate units of each kind. Determine gestures as far as possible from the hand movement and the action context alone, and rely on the accompanying speech as little as possible.

D. Anchors by conjecture

For each conjecture: the statement, its truth value, and for each form code a matched pair, one excerpt the rule codes 1 and one it codes 0, each with one line saying why. On the VR conjectures, Operative also has an example entered as 1_retold and an example of a report coded 0, where a suitable excerpt was found. Gesture anchors are described in words. The anchors are illustrative; a response may qualify in other ways, and Sections B and E decide.

D.1 Baseline

b1: Prism Diagonal (True)

"In a rectangular prism, the space diagonal connecting opposite corners is longer than any edge or face diagonal."

General.

1

"you can kind of think of it as that would be the hypotenuse of a right triangle between like the side and the base. Um, and the hypotenuse of a triangle is always longer than the sides that create it. So, um, therefore it would be longer than any, um, your face." Step 5: the participant gives a reason about rectangular prisms in general that names a part (the diagonal as the hypotenuse of a right triangle) and then says what it means for which line is longer.

0

"True. This is because, um, of the hypotenuse of the angle in the rectangular prism, making it true." Fails check 5c: the participant names the hypotenuse but never says what it has to do with which line is longer, so the fact only sits beside the verdict.

Logical.

1

"the face diagonal of the rectangular part, it's longer than any edge. And then the space diagonal is longer than the face diagonal because the face diagonal connects two points in the same plane" Two dependent steps (face diagonal exceeds an edge; space diagonal exceeds the face diagonal because it leaves the plane) lead to the conclusion.

0

"it's just gonna be longer going through the, like, volume of the prism versus the exterior lines or edges. It's just how it looks in my brain." A correct image is stated without any step that derives it.

Operative.

1

"if you have a rectangle and you just have the diagonal across that, and then as you extend that up, then you're adding, like as you add height to that original diagonal, then you're gonna be making it longer" An action on the object, told with "you": the participant raises the face diagonal by adding height to it and says what comes of it ("making it longer"), which is about which line is longer.

0

"if you're going from like inside the rectangle to like the other corner from the outside, just going corner to corner, that would be a longer space between, I feel like it's my visual." No doing: "going corner to corner" only follows a line that is already in the figure, and the participant says only that it looks longer.

Dynamic gesture. A hand held along the diagonal of a face and then raised at one end, lifting the line toward the opposite corner. The hand acts on the line by lifting it, so the diagonal is shown changing.

Non-dynamic gesture. Two cupped hands held apart to show the static box; pointing to where opposite corners sit; a finger drawing the diagonal from one corner to the opposite corner. The box, its corners, and its diagonal are shown as they are, and drawing a line that is already part of the figure does nothing to it.

b2: Polygons and Angles (False)

"The interior angles of any regular polygon always sum to 360 degrees."

General.

1

"a Pentagon has interior angles sum at 540 [...] I know shapes above shapes that have more than five sides have more than 360 degrees." Step 2: the conjecture is false, and a pentagon, whose angles add up to 540 and not 360, is a valid counterexample named clearly enough to check.

0

"regular polygon, that also includes like a rectangle. So that would be, those are all 90, 99 90, which is 180 180 360 [...] I'm gonna stick with true" The participant works out one shape, a rectangle, and gives the verdict without saying that the result holds for polygons not tried, so step 3 is not met, and a single case fails check 5a.

Logical.

1

"for a triangle, like the interior angles sum to [...] 180 degrees. And then for a rectangle it's sum to 360 degrees. And once we increase one more side, we increase 180 more degrees to the total sum" Stated cases and a rule for how the sum changes with each side form a chain to the conclusion.

0

"False because they'll only sum to 360 degrees at their rectangle. So like not pentagons or other shapes." The class that fails is named, but no step shows why it fails; the claim is asserted.

Operative.

1

"it can be like, cut it into like two triangles. So the sum of the angles in a triangle is like 180 degrees. [...] So the interior angles sum would be 180 plus 180. So it's 360." A calculation: the participant adds two stated amounts (180 plus 180) and gives the total, which is about the sum of the angles. The working is mistaken (a six-sided polygon is treated as two triangles), which does not matter for this code.

0

E. Full definitions

E.1 Intuition

Q: "What was the participant's first verdict, and was it correct?"

The initial (first-stated) true/false verdict, scored for correctness. It is locked to the first verdict; later changes of mind do not affect it.

Value Use when
1 Correct verdict, stated explicitly at the outset.
0 Incorrect verdict, stated explicitly at the outset.
1_inferred No clean explicit verdict, but a correct stance is inferable, from a minimal cue ("yeah," "no," "I don't think so") or from reasoning that stays consistent through to the end.
0_inferred As above, but the inferable stance is incorrect.
missing The participant went straight into reasoning and no verdict can be inferred at all.

Try to infer a value before settling on missing. Only Intuition may be missing; for every other code, absence means 0 (Rule C3). For i5, apply Rule C5.

E.2 Insight

Q: "Is at least one correct, relevant mathematical idea present?"

Value Use when
1 A valid idea, relationship, computation, or counterexample bearing on why the conjecture holds or fails, even if partial or loosely worded.
0 No such idea; or what is offered is mathematically wrong; or it is only a restatement of the conjecture in other words.

Insight is coded generously (Rule C2): if the spirit of a valid idea is there and nothing said is wrong, code 1. Counterexamples are judged by Rule C4, and i5 by Rule C5.

E.3 General

Q: "Does the participant say, in their own words, that the claim holds for every case, or give a specific reason about the kind of object the conjecture names (for example, triangles in general and not one triangle) and tie it to what the conjecture is about?"

Background, not needed for coding. General follows the generality characteristic of Harel and Sowder's transformational proof scheme: the participant understands "that the goal is to justify a 'for all' argument, not isolated cases and no exception is accepted" (Harel & Sowder, 2007, p. 809; see also Harel, 2007, p. 67).

The code is 1 when the participant's own words reach beyond single cases and single occasions in one of the four ways in the table, and 0 otherwise. A reason counts whether or not it is correct, because General judges the kind of reasoning and not whether it is right (Rule C1).

Value Use when
1 The conjecture is false and the participant gives a valid counterexample (step 2); or the participant extends a case to cases they did not try (step 3); or the participant says the claim is so, or is not so, for every case in their own words (step 4); or the participant gives a specific reason about the kind of object and ties it to the conjecture (step 5).
0 The participant only repeats the conjecture; or what they offer is something they did or saw, one case that they do not extend, or a doubt; or their reason names nothing specific; or it is not tied to the property the conjecture is about.

Step 1. Ignore the conjecture read back. Reading the conjecture aloud or repeating its wording is not reasoning, and the conjecture's own "any" and "always" do not count when the participant repeats them. Putting the conjecture in other words without bringing in anything it does not mention, or explaining what its words mean, counts as repeating it. If the participant gives up an earlier explanation, judge only the later one (Rule C2). Where an idea comes from does not matter, and "I remember hearing this" is not a reason. Only the conjecture is ignored; what the participant says about the video or the VR activity is checked in the later steps.

Step 2. A counterexample. Rule C4 decides whether a counterexample is valid. An invalid counterexample earns nothing in any step, and this includes a case described too loosely to check ("if one side is steeper"). Anything else the participant says is still judged in the later steps.

Step 3. A case extended. The case may be one the participant tried, drew, pictured, or watched. The extension may be in any words, as long as it speaks of cases that were not tried. These are not extensions:

  • one more case that the participant names;
  • the true-or-false answer alone after a case ("so it's true");
  • the conjecture's wording repeated after a case ("so it always does," where "always" is the conjecture's word).

If the participant uses a word for every case of their own after a case, judge it in step 4.

Step 4. The claim, said for every case. Look only at the parts of sentences in which the participant says that the claim is so or is not so.

The words for every case are: any, every, all, each, always, never, no ("no triangle"), whatever, whichever, wherever, anywhere, whenever, no matter, regardless, and in general, with their plain variants ("everything," "everywhere"). Saying that something which differs from case to case makes no difference to the property counts in the same way, in any phrasing ("it doesn't matter how big the cube is"; "how far apart they are doesn't change the angles"; "even if the lines are closer, the angles are the same").

A word for every case does not count when:

  • (a) it is the conjecture's own word said about the same objects, or a one-word swap of it ("every" for "any");
  • (b) it covers the parts of one object and not the cases ("all four angles");
  • (c) it tells only what the participant did or saw ("no matter where I moved it, it stayed");
  • (d) it is negated ("not always"), asked as a question ("is it always?"), or only possible ("it might always");
  • (e) the participant limits it to some of the cases in the same sentence ("anywhere near the bottom"; "either way," said about two named choices). Do not assume a limit that the participant does not state.

Words that say something has to be so ("must," "has to," "can't," "only") are not words for every case.

A word for every case that sits in a sentence about some other fact ("the angles of a triangle always add to 180") does not earn the code in step 4. Judge that sentence as a reason in step 5.

Step 5. A specific reason about the kind of object the conjecture names. The reason has to pass all three checks.

Check 5a. It is about the kind of object, not one occasion or one example. The reason is said about objects of that kind in general. The participant does not need to say "all" or "every": a reason that speaks of the kind of object without picking out a particular one can pass ("the more sides, the bigger the angles get"). It fails in three ways:

It fails because it is What that means Examples
told as something the participant did or saw It recounts one occasion. A reason that only explains what happened on that occasion fails too. "when I moved it"; "I saw"; "in the video the angle stayed the same"; "because the transversal stayed there"
about one case only The object is given its own numbers or shape, even invented numbers, or is one particular example. Calculating with those numbers is still one case. "a square"; "say each side is one"
a doubt It is a possibility, a question, or a search that found nothing. "it could be"; "might"; "maybe"; "I don't know if"; "I can't think of one"

A sentence with "you," "if," or "would" is not told as something done. "I think," "probably," "should," and "would" are not doubt, and neither is "could" when it means "is able to" ("you could fit two more in"). A hedge on where the participant ends up ("so I guess false") is not a doubt about the reason.

Check 5b. It names something specific. The reason names a part, a quantity, a dimension, or a relationship in the object (sides, angles, a diagonal, a distance, parallel lines, a third dimension). Saying which parts the object has or lacks counts ("no corners or flat sides"). A calculation step that uses no measurements of any one object also counts ("you multiply by two three times"). Do not ask whether the reason is clear, complete, or correct; ask only whether it names such a thing. Naming only the object or its overall shape fails ("a sphere is a ball shape"; "the whole thing is round").

Check 5c. It is tied to the conjecture. The reason reaches the property the conjecture is about, in one of two ways:

  • the reason itself says something about the property beyond saying that the claim is so or is not so, such as how the property changes, where something falls, or by how much ("the more sides, the bigger the angles get"; "they cross nearer the short side"); or
  • the participant states a fact and then says what it means for the property. What they say may be that the claim is so or is not so, in the conjecture's words or their own ("only one pair of sides is parallel, so they wouldn't cut each other in half"; "the diagonal is the hypotenuse, so it's the longest side").

A reason about the opposite situation, in which what the conjecture starts from is not so, is checked in the same way ("if one angle were off, one of the sides would come out different, so they wouldn't be similar").

The reason is not tied to the conjecture when:

  • a fact, formula, or rule is followed only by the true-or-false answer ("angles add to 180, so true"; "the formula is one-third base times height, so true"); or
  • what follows is about a different property ("they're not parallel, so they have to cross somewhere," when the conjecture is about whether they cut each other in half).

Saying only that the claim is so or is not so. If the participant says that the claim is so or is not so and adds nothing, the code is 0 ("the angles stay the same"). "Nothing" means no word for every case of their own, no fact before it, and nothing more about the property.

E.4 Logical

Q: "Does the participant state a deductive chain?"

Logical follows the logical inference characteristic: the participant proceeds as though "justifying in mathematics must ultimately be based on logical inference rules" (Harel & Sowder, 2007, pp. 809–810; Harel, 2007, p. 67), in contrast with empirical schemes that rest on examples or perception.

Value Use when
1 A valid counterexample stated with what the case produces (Rule C4); a calculation whose numbers and result are stated, even on one example; or a chain of starting point, middle step, and conclusion, in which the middle step is drawn from the starting point and then used to reach the conclusion (if–then or therefore reasoning, applying a definition or rule to a consequence, or proof by contradiction). What matters is the deductive structure, not whether every step is flawless.
0 One reason followed by the conclusion or by the verdict; a correct image or a correct conclusion without the steps that connect it; a case with only its outcome ("I tried it and it worked, so it's true"); authority offered in place of steps ("it's a theorem," "it looks right"); a bare assertion; or an invalid counterexample.

Specific numbers do not make reasoning empirical: a calculation whose numbers and result are stated (1×1×1 = 1 and 2×2×2 = 8, therefore eight times; four angles of 90, so 360) earns the code even on one example, and whether the example covers every case is General's question.

E.5 Operative

Q: "Does the participant describe doing something to the object or with its numbers, themselves or as something anyone could do, and say what comes of it?"

Background, not needed for coding. Operative follows the operational thought characteristic of the transformational proof scheme: "transformational observations involve operations on objects and anticipations of the operations' results," and the operations are goal oriented, applied either to change a relationship or to check that it stays unchanged (Harel & Sowder, 1998, p. 258); the evidence of operational thought is that the individual "forms goals and subgoals and attempts to anticipate his/her outcomes" (Harel, 2007, p. 67).

The code is about the participant operating on the object, in VR or in imagination. It is not about the participant recounting what they were shown.

Value Use when
1 The participant describes a doing (step 1), says what it produces (step 2), and that result is about the conjecture's property (step 3).
1_retold The same, on a VR conjecture, when the participant retells the VR activity with its result and the response has no other doing (step 4). It counts as 1 in every analysis, and it is marked so that the analysis can be repeated without it.
0 No doing is described; or a doing has no stated result; or the result is only about what the conjecture tells you to start with.

Step 1. Find a doing. A doing is something the participant describes carrying out. There are three kinds.

An action on the object. The participant says "I," "we," or "you" does something to the object, with a verb such as move, cut, pull, unroll, double, rotate, slide, or fold. The action may be in any tense and may come with "if," "when," or "wherever." It may have been carried out in VR or only imagined. An action said about every position at once is still an action ("wherever you cut it, it's a circle").

A calculation. The participant adds or multiplies stated numbers or amounts, or compares the totals, and says what comes out ("four angles of 90 make 360"; "two times two times two is eight").

A case made up and followed to an outcome. The participant chooses a particular arrangement that the conjecture leaves open (two equal sides, one angle of ninety, a chord through the middle, a plane that just touches the top) and says what then holds for it. The outcome has to be stated, and it has to follow from the features the participant gave the case ("if two sides are the same length, together they're longer than the third").

What is not a doing.

Not a doing What that means Examples
A report It only tells what happened or what was seen. Nobody is described as doing anything to the object: the object does it by itself, the sentence is passive, someone else does it, or the participant says only what they saw. This is the same for every participant, whether they performed the VR activity or watched it. "the lines got closer"; "when the line was moved closer"; "as he pulled the line closer"; "I saw a circle"; "in the video the sides were equal"
Repeating the conjecture Both the action and the result are the ones the conjecture itself gives, told with "you" or with nobody acting, and nothing is added (Rule C2). Saying it with "you" does not make the action the participant's own; the statements of i2 and i3 are themselves worded with "you." "if you double all the sides, it's eight times bigger"; "when you unroll it, the width is twice the distance across"
Following a line that is already there Words such as "go" that only trace or name a line or part of the figure do nothing to the object. Picturing or drawing the figure the conjecture describes does nothing to it either. "if you go from the top corner to the bottom corner"
A fact or formula stated from memory The participant states it without calculating with it. A known fact about a named shape is of this kind. "the angles add to 180"; "a triangle is 180"; "a pentagon is 540"
A conclusion drawn from one fact to another Nothing is done and nothing is calculated. Judge it separately under Logical. "two pairs of angles match, so the third does too"
A kind of case with no outcome The participant names a sort of case but does not say what holds for it. Supposing the conjecture itself to be true or false, or the object not to be what the conjecture says it is, is not a made-up case either, unless a particular arrangement, an action, or a calculation is described within it. "a trapezoid whose sides are angled differently"; "if one angle were off, one of the sides would come out different, so they wouldn't be similar"
A change named only by what it is meant to achieve The participant says what the change should bring about and not what the change is. "modify it so they don't bisect"

When a change that neither "I" nor "you" makes counts. Such a change, whether the participant reports it ("the lines got closer"; "as he pulled the line closer") or only supposes it ("even if the distance increases"), counts as a doing only when the participant goes on to follow it in their own words: they say what else changes with it, beyond the result the conjecture gives ("the angle should not change, as the line between the two would increase alongside it"). Saying why the result holds without naming anything else that changes ("because the lines stay parallel"), or adding only "so true" or "so false," does not make it a doing. When it counts, it is entered as 1, because the participant has followed the change themselves. A change and a result that are only the conjecture's own are still the conjecture repeated.

When repeating the conjecture counts. It counts as a doing when the participant adds a step or a result that the conjecture does not give ("doubling each one multiplies by two three times"). The conjecture's action and result told as what the participant did in VR ("when I unrolled it, the width was twice the distance across") is a retelling of the VR activity, and step 4 gives it 1_retold.

Adding up a shape's angles. Adding up the stated angles of a shape is a calculation and counts ("a square has four angles of 90, so 360"), whereas stating the known total for a named shape does not ("a triangle is 180").

Step 2. Check for a result. The participant says what the doing produces: the shape, size, position, or value that results; the direction of change ("more space left"); what the result is not ("not a circle or an ellipse"); or that the property changed or stayed the same. A result still counts when it is said with uncertainty, loosely worded, revised, or wrong. These are not results: a list of possible outcomes; a doubt in place of an outcome ("who's to say where the midpoint is"); an action with no outcome of its own ("you could keep sliding it").

Step 3. Check that the result is about the conjecture's property. The properties are listed in Section E.3. A result that is only about what the conjecture tells you to start with does not count ("the sides doubled"; "it formed a rectangle"). The result does not have to settle the conjecture. A result worked out on a special case of the object counts too ("cut a square along its diagonal and you get two equal parts," for a conjecture about a trapezoid's diagonals, because a square is a special kind of trapezoid).

Step 4. 1 or 1_retold. On a VR conjecture (i1 to i6), enter 1_retold when the participant retells the VR activity with its result and the response has no other doing. Words that follow the retelling and only give the answer or say the claim again are not another doing. The retelling may be told as what the participant did ("when I moved the vertex down, it met the base") or with "you" ("in the VR, when you pull the top down, it lies flat"). Enter 1 when the response has any other doing that earns the code: an action that was not part of the VR activity, a calculation, or a case made up and followed to an outcome. A case that was part of this participant's VR activity (for example, the plane just touching the sphere, for a participant who performed or watched that) is a retelling and not a made-up case. A response to a baseline conjecture (b1 to b6) is never 1_retold.

The VR activity for each conjecture. The VR activity is whatever that participant performed or watched in VR for that conjecture, which the video and the transcript show. In most sessions it is the activity below. In some sessions it is a different movement of the same shape.

Conjecture The usual VR activity
i1 pulling one parallel line toward the other until they meet, and back
i2 pulling the cube's arrows until each of its three dimensions is doubled
i3 unrolling the cylinder until it is flat, and rolling it back
i4 pulling the top corner of the triangle down onto its base, and back
i5 lowering the plane through the sphere, from first touch until it is below

E.6 Dynamic Gesture

Q: "Does at least one hand gesture depict an object, or part of one, undergoing a change?"

Value Use when
1 At least one gesture unit acts on the represented object or sets it in motion (rotating, translating, folding or unfolding, stretching or compressing, slicing, building, or moving the object along a path), so that the object is shown passing from one state to another.
0 No gesture unit does so.

Agency and kineticity. Dynamic and Non-dynamic gestures are both representational, and what separates them is whether the participant does something to the imagined object. A unit is Dynamic in either of two cases. In the first, the participant exercises agency on the object, which means that the hand acts on it, as when it turns, slides, folds, stretches, cuts, or builds the object. In the second, the gesture adds motion to the object (kineticity), which means that the hand stands for the object, or a part of it, and the hand's movement is the object's own movement or change. A unit that only depicts the object or a part of it, with no agency exercised and no motion added, is Non-dynamic (Section E.7).

The object, not the hand. A moving hand does not by itself make a gesture Dynamic, because hands also move in order to depict. They move into position, outline a shape, trace a line that is already part of the figure, or point, and such movement belongs to the depiction and leaves the object as it is. Two anchors mark the boundary. (a) A flat hand, standing for the plane, descends onto a fist, standing for the sphere, and stops as it touches. This unit is Dynamic, because the plane is shown moving into the sphere. (b) The flat hand is brought into place above the fist and held there while the participant talks about the contact point. This unit is Non-dynamic, because the hand only takes up a position and nothing is done to the object.

Gesture unit. A gesture unit begins and ends in the resting position (Rule C7). The unit is what is judged, and the response is what is coded, so the code is 1 when at least one unit in the response qualifies.

Tracing. If the object is moving and the hand traces its path as if carrying or moving the object, the unit is Dynamic. If the hand traces along a line or arc that is already part of the figure, the unit is Non-dynamic.

E.7 Non-dynamic Gesture

Q: "Does at least one hand gesture depict an object, or part of one, held static?"

Value Use when
1 At least one gesture unit only depicts the object or a part of it (showing its shape, outline, size, or location, pointing to or holding a part, or tracing a line or arc that is already part of the figure), with no agency exercised on the object and no motion added to it.
0 No gesture unit does so.

A gesture unit begins and ends in the resting position (Rule C7). A single response may contain both Dynamic and Non-dynamic units, so score each code independently for whether at least one unit of its kind occurs.
